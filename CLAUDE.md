Проект — самописный фреймворк на чистом Python с реализациями современных
алгоритмов сортировки по научным статьям из каталога `papers/`.

## Архитектура (кратко; подробно — claudedocs/architecture.md)

- `src/sorting_lab/algorithms/` — один файл на алгоритм, класс-наследник
  `Algorithm` с паспортом `AlgorithmInfo` и методом `sort(data, compare)`.
  Регистрация — в `algorithms/__init__.py` через `register(...)`.
- `src/sorting_lab/datasets/` — генераторы входов с параметром `seed`
  (воспроизводимость обязательна) и эталонные крайние случаи.
- `src/sorting_lab/bench/metrics.py` — метрики прогона: число сравнений
  через `CountingComparator`, время, число инверсий входа.
- `tests/` — pytest; тесты корректности автоматически охватывают все
  реализованные алгоритмы из реестра.

## Правила, обязательные для любого изменения кода

1. **Комментарии и docstring — на русском языке.** Каждый модуль начинается
   со строки документации: идея алгоритма и ссылки на статьи из `papers/`.
   Класс — паспорт `AlgorithmInfo` со ссылкой на статью-источник. Неочевидные
   шаги алгоритма поясняются комментариями.
2. **Сравнение элементов — только через компаратор** (`compare(a, b)`),
   никогда напрямую оператором `<`/`>`; иначе ломается подсчёт сравнений
   в измерительном стенде.
3. **Один файл — один алгоритм**; имя файла совпадает с `info.name`.
4. **Никакого легаси и переключателей старое↔новое**: новое поведение
   заменяет старое полностью, старый код удаляется в том же изменении.
   Флаги конфигурации и A/B-ветки не добавлять.
5. Генераторы данных всегда принимают `seed`; одинаковый seed обязан давать
   одинаковый массив.
6. После изменения кода запускать тесты:
   `.venv/Scripts/python.exe -m pytest` (хук запускает их автоматически
   после каждого редактирования файлов проекта).
7. Аналитические документы, отчёты и обзоры — в `claudedocs/`, не в корне.
